## 🔴 Vấn Đề Nghiêm Trọng (Phải phẫu thuật / xử lý ngay)

### 1. Ổ bão hòa Log 33MB do lỗi xung đột Telegram 409 Conflict & Lộ Token
- **Vị trí phát hiện:** `backend/logs/site_contract_bot.log` (~33.1 MB)
- **Triệu chứng bệnh:**
  - File log đang bị ghi liên tục mỗi **4 giây** với lỗi:  
    `Telegram API getUpdates error: Conflict: terminated by other getUpdates request; make sure that only one bot instance is running (code 409)`
  - Toàn bộ URL request của Telegram chứa Token xác thực `bot8874474590:AAFN...` bị ghi thẳng vào file log dưới dạng cleartext (Plain text).
  - Xuất hiện hiện tượng **Double Logging (ghi trùng 2 lần mỗi dòng)**: do `backend/run_workers.py` vừa redirect `stdout/stderr` của tiến trình con vào file log, vừa cấu hình `logging.FileHandler(log_file)` bên trong `site_contract_bot.py`.
- **Hậu quả nếu không điều trị:**
  - **Tràn ổ cứng:** Mỗi ngày sinh thêm hàng chục MB log rác vô nghĩa.
  - **Bảo mật:** Bất kỳ ai có quyền đọc file log đều chiếm được toàn quyền điều khiển Telegram Bot TVT3.
  - **Kẹt tiến trình Bot:** Bot không thể nhận tin nhắn hay lệnh mới từ người dùng do bị ngắt kết nối polling liên tục.
- **Phác đồ điều trị:**
  1. Truncate (làm sạch) file log 33MB về kích thước 0.
  2. Bổ sung `RotatingFileHandler` (giới hạn file tối đa 5MB, lưu tối đa 3 file xoay vòng) thay cho `FileHandler` thông thường.
  3. Bỏ việc vừa pipe `stdout` vừa dùng `FileHandler` để tránh double log.
  4. Kiểm tra và chấm dứt tiến trình bot Telegram chạy trùng lặp ở nơi khác đang tranh chấp token.
